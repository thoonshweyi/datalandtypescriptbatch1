🔹 What is Webpack?

Webpack is a module bundler.
Its main job is to take all your project files (JavaScript, CSS, images, etc.), treat them as modules, and bundle them into one (or more) optimized files that the browser can load efficiently.

🔹 The Bundle Process (Step by Step)
1. Entry

Webpack needs to know where to start bundling.

This is the entry point (usually src/index.js).

From this file, Webpack builds a dependency graph by looking at all import / require statements.

// webpack.config.js
module.exports = {
  entry: './src/index.js',
};


👉 Example: If index.js imports app.js and style.css, Webpack includes them in the graph.

2. Dependency Graph

Webpack analyzes your code.

Whenever it sees import or require, it follows that file.

It recursively collects all the dependencies into a graph (like a tree).

👉 This graph ensures Webpack knows what depends on what.

3. Loaders

Browsers can only understand JavaScript, HTML, and CSS, not other formats (like TypeScript, JSX, SCSS, images, etc.).

Loaders let Webpack transform these files into valid modules.

Examples:

babel-loader → transpile modern JS/React (ES6+ → ES5)

css-loader → allow importing CSS

style-loader → injects CSS into the DOM

file-loader / url-loader → handle images and fonts

module.exports = {
  module: {
    rules: [
      { test: /\.css$/, use: ['style-loader', 'css-loader'] },
    ],
  },
};


👉 So when Webpack encounters a .css file, it runs it through these loaders.

4. Plugins

Plugins extend Webpack’s functionality beyond file transformation.

Example plugins:

HtmlWebpackPlugin → automatically injects bundles into index.html

MiniCssExtractPlugin → extracts CSS into separate files

CleanWebpackPlugin → cleans old builds before bundling

👉 Loaders = transform files
👉 Plugins = perform broader tasks

5. Output

After building the dependency graph and applying loaders/plugins, Webpack bundles everything into one or more files.

These are placed in the output directory (e.g., dist/).

module.exports = {
  output: {
    filename: 'bundle.js',
    path: __dirname + '/dist',
  },
};

6. Optimization

Webpack optimizes your bundle:

Minification (remove whitespace, shorten variable names)

Tree Shaking (remove unused code)

Code Splitting (split into multiple smaller bundles for performance)

Caching (add hash to filenames for browser cache)

7. Serve / Deploy

In development, you often use webpack-dev-server for live reloading.

In production, you deploy the optimized dist/ folder to a server/CDN.

🔹 ***********Visual Summary***********

Entry → Webpack starts from index.js

Dependency Graph → collects all imports/requires

Loaders → transform files (TS → JS, SCSS → CSS, etc.)

Plugins → enhance functionality (HTML, CSS extraction, cleaning)

Output → bundles everything into dist/bundle.js

Optimization → minify, split, tree-shake

Serve → run locally or deploy
